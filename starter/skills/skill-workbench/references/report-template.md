# Skill work report

Use only sections that have something concrete to report.

```markdown
## Changes

- **<skill name>**: <what changed and why>
- **Documentation**: <relevant indexes or support files updated>
- **Validation**: <checks and scenarios actually run>

## Remaining issues

- <unresolved finding, or omit this section>
```

For a small change, a short paragraph is enough. Do not include implementation details
that do not help the reader understand the result.
